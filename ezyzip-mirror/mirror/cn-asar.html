为什么客户端解压 ASAR 比服务器端工具更快

ezyZip 使用客户端 WebAssembly (WASM) 在本地处理 ASAR 压缩包。以下是我们的引擎优于服务器端解压工具的原因：

  • 无上传/下载等待解压速度仅受限于您本地的 CPU 和磁盘 I/O，而非网络连接速度。一个在普通网速下需要 20 分钟上传的 2 GB 压缩包，在本地可在数秒内解压完毕。
  • 多引擎故障转移如果某个解压引擎遇到罕见错误，ezyZip 会自动切换到备用解压器。这种级联方式支持超过 250 种压缩格式，并能处理非标准文件头或混合压缩方式等边缘情况。
  • 大文件支持借助 File System Access API 和 Origin Private File System (OPFS)，ezyZip 将数据直接流式写入磁盘，避免了其他基于浏览器的工具常见的内存崩溃问题。几乎任意大小的压缩包都可以在不耗尽 RAM 的情况下解压。
  • 专用工作线程解压在独立线程的专用 Web Workers 中运行，浏览器界面始终保持完全响应。您可以监控每个文件的解压进度、预览已解压的文件，并在解压于后台运行时继续浏览网页。
  • 高级内存管理对于超大压缩包，我们的 Memory64 WebAssembly 构建版本突破了标准浏览器内存限制，让您能够解压那些会导致其他网站崩溃的文件。这种扩展寻址模式支持远超典型 4 GB WASM 内存上限的压缩包。
